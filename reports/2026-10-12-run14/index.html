Our flyvis motion test, second attempt: what happened

Our own test · pre-registered · stopped by a fixed rule · no reading for either model

12 Oct 2026 · sensory models · our own test · second attempt · no result

In short

The question: does the real wiring layout help a trained fly vision model see which way things move? We shuffle the layout in flyvis, a trained model of the fly's motion-vision circuit built on its connectome (within each pair of cell types, the synapse counts swap places between neighbouring positions), then check whether the motion-sensitive cells still prefer the right directions.

Not decided: a second, lower-memory attempt on 12 Oct also needed more memory than our shared machine has (about 3 GB at its peak; the machine allows 3 GB for everything running on it).

Measured: it ran out while preparing the moving-edge test input, before the first simulation step (sampled peak about 3.17 GB of the 3.22 GB limit, which is 3 GiB). There is no reading for either model, so nothing enters the controls ledger and there is no chart.

What the test can and cannot ask. We did not retrain the model after shuffling. A model trained on the shuffled wiring might do better, so this asks a narrower question: does this trained model depend on the real layout? The light-versus-dark (ON/OFF) test cannot tell real from shuffled wiring here: the shuffle keeps each connection's sign and total strength, and the authors report that signs alone are enough for it.

10 Oct 2026 First attempt: "Not decided: the test did not run, because it needed more memory than our shared machine has. A pre-registered setup check also failed, so no result would have been read." Report of 10 Oct 2026

Model and code: flyvis (TuragaLab, MIT licence; we installed version 1.2.0) and its pretrained models; paper: Lappalainen et al. 2024, Nature (PMC11525180).

The steps, in order

The pre-registration fixed a sequence of checks before any reading. Each one had to pass before the next could start.

Install and modelsPassedThe installed software took about 1.0 GB of temporary space, which on this machine counts against the same memory limit. The two pretrained models we use (000 and 024) came from the authors' public download and matched its checksum.

Memory and timing checks, then the testNot reachedNo reading for either model; no ledger row, no chart.
  • Why the public sentence says "about 3 GB at its peak": the machine stops a process when it reaches its 3 GiB limit. Our sampler, which reads memory twice a second, last saw about 3.17 GB (decimal), so the true peak reached the limit.
  • What was not measured: the lower-memory loop itself never ran, so we do not know how much memory it needs. That the jump came from building the moving-edge input is our reading of the timing, not a profile; the 10 Oct attempt also stopped inside a step that builds a test input and then simulates.
  • A possible next attempt (not yet tried): build the test inputs in a separate step with no network loaded, save them as small files, and measure that step alone before running the loop on them.
  • Clean-up: all temporary files were deleted after the stop, and memory use fell back to about 0.34 GB.

One new ledger row: a StepMania player

Authors' own numbers · not recomputed by us · scored only by our fixed rules, no override

  • Helps duth-x-stepmania (grade A; new entry): duth-x-stepmania: the authors compared the real wiring with 3 degree-preserving rewired copies (mean) on StepMania hit rate on the 152-note Edit chart. Real 0.9737, null 0.4013 (3 null samples). Our ledger rules read this as helps. Quality: fair, moderate (source results/play_test.json at c6b829d).
  • Caveats: one seed and no statistics; only 3 rewired copies, and only their mean is committed; the readout groups (which cells count as up or down presses) are taken from the real wiring and reused on the rewired copies, which may favour the real circuit; there is no no-brain baseline; the threats are injected straight into detector neurons, so there is no vision.
  • Other charts in the same file point the same way (real against rewired mean: Beginner 1.00 vs 0.47, Hard 0.84 vs 0.35, Challenge 0.93 vs 0.45); only the Edit chart is scored.

2 new entries, each graded from its code

Each repository was read at a fixed commit; the basis for each grade is in its catalogue record. Project claims below are the projects' own, not our findings.

  • A duth-x-stepmania (abstractionthief, MIT, commit c6b829d): a 766-neuron looming-escape circuit from the MaleCNS v1.0 male fly connectome runs as a rate model. Each StepMania note becomes a looming threat, and a fixed readout of its descending neurons picks the arrow. The same chart is played by 3 degree-preserving rewired copies. Graded A on its code-level control only; the task is easy by construction, because each threat collides exactly on its note.
  • B flyonenomics (uguryildirim24, MIT, commit 8f3c223): a spiking model of the male fly nervous system on MaleCNS v1.0 for simulated dopamine and transmitter changes, with hand-made input injection. Its README reports spike activity only and says this is not treated as animal behaviour. No wiring control, so no ledger row. Graded from a short reading; the engine and statistics code were not read line by line.
