Does the real wiring layout help a trained fly vision model see which way things move?

10 Oct 2026 · sensory models · our own test · not run

In short

The question: does the real wiring layout help a trained fly vision model see which way things move? We planned to shuffle the layout in flyvis, a trained model of the fly's motion-vision circuit built on its connectome: within each pair of cell types, the synapse counts swap places between neighbouring positions. Then we would check whether the eight kinds of motion-sensitive cells (T4 and T5) still prefer the right directions.

Not decided: the test did not run, because it needed more memory than our shared machine has. A pre-registered setup check also failed, so no result would have been read.

  1. Done Install. flyvis 1.2.0 on CPU and the authors' pretrained models (the download matched its published checksum). The install measured 1.40 GB, over our 1.35 GB limit, and was trimmed to 1.00 GB.
  2. Failed Setup check, written down before any simulation. We expected 2,140 connection entries in 605 cell-type pairs (from the connectome file). The loaded model has 2,355 in 604: the package adds 1-synapse placeholders inside each pair. Under our rules this alone stops the test. The missing pair is not explained yet.
  3. Stopped 3 times One short simulation. A 600-frame flash on the 45,669-cell model (best-trained model, real wiring) was stopped three times for lack of memory, at a peak of about 3.0 of the 3 GiB our shared machine allows.
  4. Not run The motion test itself. Real layout against 5 shuffled layouts and an even-spread version (each pair's total spread evenly) in 2 of the 50 models, plus a no-wiring floor in one: 0 of 15 planned evaluations ran, so there is no reading for either model.

What the test can and cannot ask. We did not retrain the model after shuffling. A model trained on the shuffled wiring might do better, so this asks a narrower question: does this trained model depend on the real layout? The light-versus-dark (ON/OFF) test cannot tell real from shuffled wiring here: the shuffle keeps each connection's sign and total strength, and the authors report that signs alone are enough for it.

Next attempt: planned for run 14. It needs a leaner simulation loop that keeps only the cells it reads, not just more memory. There is no result, so nothing enters the controls ledger and there is no chart. Details of each step follow below.

Model and code: flyvis (TuragaLab, MIT licence, commit 92b3845c) and its 50 pretrained models; paper: Lappalainen et al. 2024, Nature (PMC11525180).

The design, written down first

  • Model: flyvis 1.2.0 (TuragaLab, commit 92b3845c) with the authors' pretrained models; two of the 50: the best-trained (000) and a typical one (024). CPU only.
  • Shuffle: within each pair of cell types, the stored synapse counts swap places between neighbouring positions (5 shuffles per model, up to 5 more as fill). Each connection keeps its sign and each pair keeps its total strength. Beside them: an even-spread version (each pair's total spread evenly) and, in model 000 only, a no-wiring floor.
  • Measure: how many of the 8 kinds of motion-sensitive cells (T4a-d and T5a-d) still prefer the known direction of moving edges. Chance is 2 of 8.
  • Setup check: if the unshuffled best-trained model did not reproduce the known directions (at least 6 of 8), there would be no wiring reading at all.
  • Before any evaluation, four checks on the loaded model had to pass, among them the number of connection entries and cell-type pairs we had counted in the connectome file.
  • Timing rule: if memory passed 2.6 GiB at the smallest batch, stop the test and publish it as "not run" with the measurement.

Why it ran out of memory

From reading the code: one simulation fills a stimulus buffer for every frame and all 45,669 cells, and also keeps every frame's full activity before stacking it. So one 600-frame sample holds at least three copies of a tensor of about 110 MB, plus temporary arrays over 1.5 million connections. The process grew by more than 0.8 GB for one sample. The exact peak of the process is unknown, because it was stopped. The memory figure is shared with our own agent processes (about 0.3 GB) and with the 1.1 GB of scratch files.

Deviations, in plain words

  • The install went over its size limit; we trimmed it instead of stopping.
  • Some method details were fixed before any evaluation: a rule that every changeable pair really changes, the package's default moving-edge settings at one speed, and flashes at one size.
  • The timing rule was applied on memory.
  • Check (a) failed, and check (c) has 293 changeable pairs.
  • The public sentence for this case was not among the two we had written in advance ("our setup did not reproduce the known motion directions" and "too few shuffles finished in time"); both would be wrong here, so we use "it needed more memory than our shared machine has".
  • No ledger row was built, because there is no result.

None of these touched a reading, because no reading was produced.

What the next attempt needs

  • A leaner simulation loop that keeps only the cells it reads and feeds the stimulus in short chunks; the process must stay under about 1.2 GB.
  • A smaller install (about 1.0 GB), and one measured flash sample before any timing.
  • The pre-registered counts taken from the loaded model (2,355 entries, 604 pairs, 293 changeable), a decision on whether the shuffle should move the 1-synapse placeholders, and an explanation of the missing pair.

Three new entries, each with its own wiring control

All three compare real wiring with shuffled or null wiring in their own code. All numbers are the authors'; we read them in their committed files and did not re-run them. Their rows join the controls ledger in a later check, so the ledger's counts do not include them yet.

  • fly-distill A: the larval connectome (2,952 neurons) as the frozen core of a small byte-level language model, 4 seeds. It found no difference from shuffled wiring: 3.957 bits per byte for the real connectome against 3.917 for a degree-preserving shuffle (lower is better). A random graph did best (3.523). A language task, not fly behaviour; not peer reviewed.
  • flywire-connectome (mushroom body on BANC) A: a simple rate model of the mushroom body, the smell-learning circuit, on the BANC v888 connectome, against pre-registered null wirings that keep each neuron's connection strength. Mixed: the real wiring was slightly worse at telling odours apart (95.3% against 95.7% for the nulls' median), significant on the right side only. Documentation in Korean; the author draws no conclusions about disease.
  • brainlab A: the FlyWire v783 whole-brain spiking model with real, shuffled and disconnected wiring under the same sugar stimulus, 5 seeds. Only the activity differs: the real wiring gave about 3.7 times the spikes of the shuffled one. There is no task, so it does not test whether the wiring helps. Grade A is a judgement call; B is arguable.

Correction: Fly With Me (grade B unchanged). Its "Is it AI?" class changes from "No trained part" to "Whole network or synapses trained". At commit 89b130d its server loads 9,978 trained synapses onto 25 descending neurons by default, although a line in its TRAINING.md says the connectome on the main branch is never changed. We follow the code. With it, 55 of 94 graded projects have a trained, learning or search-tuned part.

A fourth candidate waits for the next check (we admit at most 3 per check).

Method and limits

  • The flyvis question is untested: nothing can be said about the wiring layout and motion direction. Even a run that works would only ask whether this trained model depends on the real layout, in 2 of 50 models at one stimulus speed.
  • The memory peak is a lower bound for one sample and is shared with our agent processes. We attribute the stops to our own process from the exit codes and the timing.
  • Our explanation of check (a) uses our own estimate of the placeholders, not the package's code path, so the 2,380 total is approximate against the 2,355 measured.
  • No model file, connectome or rendering was copied into our site; all scratch files were deleted at 10:13 UTC.
  • New grades rest on the authors' result files as read by us, not recomputed. The scan covers two search pages per term at one moment; TikTok, Instagram, X and Reddit are not covered.
